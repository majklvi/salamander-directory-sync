# Standalone plugin development rules

- Start with [HANDOFF.md](HANDOFF.md) for project identity, approved decisions, current release evidence, local test resources and the next proposed task. Then read the current user guide, changelog and roadmap relevant to the task. A new chat does not automatically inherit another chat's transcript.
- Select this checkout explicitly before repository operations: `C:\Samandarin\salamander-directory-sync`, `origin` = `https://github.com/majklvi/salamander-directory-sync.git`, branch `main`. The local path is machine-specific; on another machine use this repository's root. Do not develop or push plugin changes in the historical `C:\Samandarin\directory-sync-plugin` checkout or the original fork unless explicitly requested.
- Current verification scope is local NTFS. Do not start SMB tests or change the SDK/host APIs without an explicit new request. Keep reliability at the level of the host's ordinary file operations; do not introduce a transactional filesystem backend or expand historical fault campaigns without a concrete need.
- Preserve binary compatibility with the current Samandarin 0.16 SDK. Update the pinned SDK dependency only when explicitly requested; do not require new host interfaces.
- Use wide Win32 APIs and preserve long and Unicode paths. Do not introduce `MAX_PATH` buffers or ACP round trips where wide data is already available.
- Follow Salamander's compact native dialog layout: `MS Shell Dlg` 8, small standard gaps, OK/Cancel, English and Czech localization, and host-controlled appearance. For unsaved changes use the conventional Save / Don't save / Cancel buttons, not radio choices followed by OK. Do not introduce a separate visual style.
- Translate Cancel consistently as **Zrušit** in Czech buttons, help text and documentation, including operation-error and transfer dialogs. Preserve the existing cancellation behavior.
- Execute only the confirmed visible eligible proposals, not just highlighted rows. Keep proposal editing separate from execution and distinguish confirmation exclusions, manual Skip, execution skips, dependency blocks and unstarted work in summaries/exports.
- Preserve staging, data/metadata verification, and the remembered Keep originals preference. Directory deletion must be explicitly planned and limited to empty directories; never fall back to recursive deletion after an error.
- Preserve approved D1–D5 and R1–R5 as summarized in HANDOFF.md. New configurations have Keep originals OFF; enabling it requires a valid recovery directory. Recovery, appearance, error policy and speed limit are global, not profile contents. Never silently continue a destructive operation without its promised saved original or retry an already published operation.
- Use Computer Use and its current skill instructions for live application interaction. Use isolated fixtures/private host configurations and preserve the user's installed host/IDE windows and configuration. Local evidence outside the repository is not automatically available to a new machine or chat.
- Build, test, and package through this repository's `tools/` scripts. Do not depend on the surrounding host checkout, shared host property sheets, a local certificate, or a global output directory.
- Verify all five x64 test suites in Debug and Release, together with the relevant build matrix. An ARM64 build is not a runtime test. Do not claim SMB, live GUI, or actual cloud CodeQL verification without performing the corresponding check.
- Preserve licenses and provenance for vendored files. Do not rewrite dated historical reports as statements about the current state.
- Keep HANDOFF.md and ROADMAP.md current when decisions or development state change; retain dated evidence and link it. Preserve the strong ALPHA/data-loss/no-warranty warnings in user-facing release materials. For documentation-only changes, check links, references and the diff; do not repeat GUI or filesystem fault campaigns. After pushes inspect this repository's current-commit CI and report pending/unavailable checks accurately.
- Active development is in `majklvi/salamander-directory-sync`, branch `main`. Check this repository's own CI; do not use the original fork's validation helper. Publish releases or make destructive history changes only when requested by the user.
