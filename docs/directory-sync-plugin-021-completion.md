# Completing 0.2.1 — 2026-10-18

This extends the existing unsaved-profile close prompt. Version 0.2.1 remains a development alpha; the published download is still 0.2.0. No SDK changes or SMB tests are included.

## Implemented: physically empty directory copies

The existing new-copy executor now accepts single-sided, physically empty directory proposals in either direction. The command is named **Copy visible new items…** and its confirmation separates files, directories and data bytes. It retains visible-plan scope, Skip, result filters, progress and Stop. The proposal menu can skip, restore or mark the valid copy direction of an empty directory. Existing targets, common directories and nonempty directory creation as an independent proposal are excluded; required parents still follow existing copy behavior.

Directories use owned sibling staging, verification and same-volume publication without replacement. The source must still match its scanned identity/metadata, remain physically empty and have no ADS. New directories inherit target permissions and preserve modification time plus supported read-only/hidden/system attributes. Existing targets are never merged or overwritten. Unpublished owned staging is removed with a nonrecursive directory removal; failures report the remaining path. Completed directories and required created parents are not rolled back after Stop or a later error.

Added ordinary local filesystem tests cover both directions and Unicode names, timestamps, Skip/filter omissions, Stop before publication and after completion, a source populated after scanning, an appearing target and unsupported directory ADS. Production proposal helpers now cover Skip, the valid direction and restoring the empty-directory proposal. This is automated local execution, not a live-host empty-directory copying test.

## Implemented: profile import/export

Two compact buttons in Manage profiles open the Windows file dialogs. Export writes the displayed profile collection, including manager draft edits, immediately to a `.dsprofiles` file. It uses the existing bounded/versioned binary profile format (signature `DSP1`, UTF-16LE fields, at most 16 MiB/1,000 profiles), with no active-selection preference. An owned temporary file is flushed and published only after the full write; failed exports do not intentionally replace an existing export. Export is independent of the later manager OK/Cancel.

Import validates the whole collection, path/mask syntax and limits before appending profiles to the manager draft. IDs are reassigned locally. Case-insensitive name collisions receive ` (2)`, ` (3)`, etc.; long names are shortened without splitting a surrogate pair. Original profiles and active selection are retained. Manager OK persists the additions, Cancel drops them. Import alone never applies profile inputs, clears current results or starts an operation. Paths are portable data, not remapped or executed, and may require editing on the destination computer. Recovery and appearance remain global and are excluded from transfer.

Storage tests cover Unicode round-trip, repeated additive imports/name collisions, new IDs, preserved active selection, malformed input with no partial append and empty-import refusal. Existing decoder tests cover truncated/oversized fields, invalid Unicode, duplicate IDs/names, unknown versions and unsupported flags.

## Combined synchronization — approved and implemented

The user explicitly approved the following ordering and first-error/Stop behavior before implementation. The combined executor is now available through **Synchronize → Execute visible plan…** and the Visible plan context submenu; separate commands remain available.

Approved behavior:

1. Freeze all visible eligible proposals and the recovery preference. Show one compact confirmation with separate file/directory counts, both directions, copy/overwrite byte totals, delete counts and recovery ON/OFF/path. Skip, hidden, blocked and unresolved entries are omitted explicitly; highlighting does not narrow the plan.
2. Create new targets (files and physically empty directories), then overwrite existing files, then delete right-only files and finally eligible empty directories deepest first. Existing recovery and metadata rules apply to each destructive phase.
3. Stop or the first error stops the whole batch, including later phases. Completed changes stay; no automatic rollback or silent continue. Show a combined result with completed, failed, pending and recovery/journal paths, then require Compare again.
4. Cancellation during the confirmation writes nothing. Close during a running batch requests Stop and joins before any dirty-profile question.

The adapter reuses the existing executors. Between phases `AdvanceExecutionSnapshot` performs a fresh metadata scan, checks canonical roots, original root/ancestor identities and attributes, and every remaining confirmed source/target stamp and presence. Only after those checks does it replace the validation baseline; the original row model, actions and indices remain frozen. Each executor still performs its normal revalidation and per-item checks. Changes to already completed or otherwise unexecuted rows do not become new operations. This is not a filesystem transaction or a claim to detect every hostile concurrent change. Recovery root location is checked before the first write if destructive phases need recovery. Recovery manifests/journals remain separate per destructive phase, and all available paths appear in the combined result.
