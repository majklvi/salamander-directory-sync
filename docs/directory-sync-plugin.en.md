## Modeless window (0.3.0)

The main synchronization window is independent and modeless. You can switch back to Samandarin and work with its panels while this window remains open, including during comparison and transfers. Opening the plugin again activates the existing window. Paths and panel selections are captured when opening it; navigating the host panels does not redirect an existing comparison or operation. Settings and confirmations belong to the plugin window, not to the host main window. Changing files through the host can invalidate a comparison: compare again before proceeding.

[Implementation and verification](directory-sync-plugin-modeless.md).

Close during an operation requests cancellation and waits for the worker. Completed changes remain; the existing modified-profile Save / Don't save / Cancel prompt still applies. The plugin keeps one preview at a time. This does not add the host's transfer queue or scheduling.

## Transfer progress (0.3.0)

Confirmed file operations open a compact progress window laid out on the host copying dialog's grid. It uses the host's actual SDK progress bars and split-button control, with centered percentages and host-controlled colors. Source/target paths are ellipsized on screen and complete in tooltips. The status line shows copied data, transfer speed and estimated time remaining when available, and identifies verification. Sizes use the host's transfer-dialog formatter with at least three significant digits and the local decimal separator, independently of the panel size-display option. Its tooltip retains the phase, completed steps, copied bytes, verification reads and elapsed time. Verification reads include both source and copy; they are not counted as copied data.

The total bar weights work by data size, including copies of originals. A file's estimated cost is its main-stream size multiplied by three for copying and verification reads from both source and copy, with a minimum cost of 4 KiB; directory and deletion steps also have a minimum cost. Named streams are not scanned in advance, so this remains an estimate and may stay at 99% until all steps finish. The current file bar switches from copying to verification; directory operations use an indeterminate file bar. With a speed limit, the time estimate is hidden while planned copying remains: verification reads are unrestricted and cannot be predicted from the limited copy rate. Copied bytes, speed and progress remain visible.

The footer offers **Minimize**, **Pause/Resume** and **Cancel**. The arrow beside Pause/Resume opens **Pause/Resume** and **Set speed limit…**. Pause takes effect at a safe worker checkpoint; Resume continues the same batch. The optional limit uses a positive whole number in B/s, KB/s, MB/s or GB/s, up to 1 TB/s, and applies to copied main data, named streams and recovery copies. It does not throttle verification reads. The limit belongs only to this batch: the next operation starts without a limit. Cancelling the speed-limit dialog preserves the current value.

**Cancel**, Escape and the window's close button request cancellation, including while paused. The window stays open until the worker finishes stopping; already completed changes remain. Minimize affects only the progress window, which has its own taskbar entry for restoring it. The main preview remains locked during the operation. The host panels remain available; this does not add host transfer-queue participation. Comparison alone continues to use the main window's progress.

In Stored originals, item-menu commands explicitly say **Copy … path to clipboard** or **Open … directory in Explorer**. Opening can fail if an original's parent directory no longer exists or Explorer cannot handle the path.

## Stored originals (0.3.0)

Available since **0.3.0 ALPHA**. Open **Settings → Stored originals…** to read sessions under the configured recovery directory. Keep originals may be off. A draft recovery-directory value in Settings is used without saving the settings first. Reading this overview never starts synchronization. A session here is one recorded attempt to preserve originals, including an incomplete attempt; it is not the lifetime of the plugin window or a saved profile. A combined synchronization can create separate overwrite and deletion sessions.

Select a session above to see its items below: original path, saved path, recorded main-stream size (in the host's units), recovery-copy status and recorded operation result. Sessions are ordered by their current directory creation time, newest first. Double-click a session or item for full paths and error codes. **Copy original / Copy saved**, or **Ctrl+C / Ctrl+Shift+C** in the items list, copy the full Unicode paths. In the sessions list the same shortcuts copy the session or manifest path. Context menus also offer path copying and opening directories. Directory buttons open Windows' file browser; files are never launched. A deleted original's parent directory may itself be missing.

**Refresh** (or F5 in a list) rereads the directory and retains the selected session if it is still present. Loading runs on a worker; closing requests cancellation and waits for the read to finish. The resizable native dialog follows the host's appearance. It does not save its window geometry or column widths.

“Saved (recorded)” means the manifest records a successful verified save and the copy currently has the expected type and main-stream size. **It is not a fresh verification of contents, ADS or metadata.** “Replaced/deleted (recorded)” comes separately from the operation journal. A missing result means **not confirmed**, not proof that no operation happened. Incomplete/damaged records, missing copies, type/size changes and unsupported schemas remain visible with warnings. Refresh after external changes; this is a snapshot, not a live monitor.

Only the current `pair-* / run-*` schema-1 layout is supported. Paths are absolute; moving a recovery tree does not rewrite its records. Reparse traversal and saved paths outside their session cannot be opened. A missing or inaccessible recovery root is reported, never created. Display limits are 1,000 sessions, 20,000 total items and 8 MiB per record file; reaching a limit produces a warning. This first stage has **no automatic restore or backup cleanup**. Use the manual recovery procedure below and keep independent backups.

## Export comparison and operation results (0.3.0)

Choose **Synchronize… → Export comparison and results…** or the same command in the results context menu. The native Save dialog offers **CSV** and **Text**; its selected file type determines the format. Export becomes available after a comparison, including an empty, cancelled or failed comparison, and remains available after execution invalidates the plan. It is disabled while work is running. Export never validates or executes a synchronization plan.

Both formats include **all rows loaded by that comparison**, not only visible or highlighted rows. Each comparison row records its default/current proposal, Skip, state/reason/errors, available left/right paths, type, exact main-stream byte size, UTC modification time and attributes. Items excluded by the scan mask/options and never loaded cannot be listed. Comparison metadata records the scan's actual options and time tolerance, mask/selected roots, current profile, cancellation/staleness, active display filters and any pending comparison-option changes. GUI sorting, hidden columns and relative size/time presentation do not remove or transform report data; rows follow model order.

The report also contains the **last confirmed operation or combined batch for this comparison**, if any: frozen execution filters, row visibility at execution, recovery choice, start/finish times, errors, planned targets/sources and returned outcomes. Recovery saves have their own records and saved paths. Combined new copies, overwrites and deletions remain separate step kinds. Immediate recycling/permanent deletion is identified separately. `filesystem_changed=true` does not imply `completed=true`: a published/removed target followed by an error remains a failed/incomplete result. `not_reported` means no outcome was returned for that step; it is not proof that nothing happened. A worker exception also makes the batch incomplete. Records are a results snapshot, not a chronological, crash-safe execution journal.

Changing filters after execution changes `visible`, while `execution_visible` retains the confirmed scope. Export does not refresh file metadata after a write: comparison rows describe the original scan and are marked stale. A new comparison or invalidating the paths/mask clears the previous operation report. Closing the window loses this in-memory report; existing recovery manifests remain independent. Export before comparing again or closing if you need it.

Files use **UTF-8 with BOM**, CRLF, stable English field names/codes and exact numerical bytes/UTC FILETIME ticks. CSV uses a comma separator, quotes every field and doubles embedded quotes. For spreadsheet safety, text with leading formula prefixes receives an apostrophe; import columns as text when retaining very large integers exactly. Text output uses sections and `key: value` lines, escaping backslashes and control characters as `\\`, `\r`, `\n`, `\t`. An absent side has blank fields, not a zero-byte file.

Save to an existing directory **outside both compared trees and the configured/current batch recovery roots**. Reparse parents are refused. The native dialog confirms replacement of an existing report. A complete temporary file is flushed and renamed in the output directory; a failed replacement preserves the previous report. Export creates no directories and changes no compared files. Large exports run synchronously with a wait cursor; there is no progress/Stop control during report generation/writing in this first implementation. The export contains paths and file details, so review it before sharing it in a bug report.

## Profiles (0.2.0)

Since **0.2.1**, closing the main window with a modified saved profile offers three buttons: **Save**, **Don't save** and **Cancel**. Cancel keeps the window and edits open. Save validates directory paths and masks; a failed save keeps the window open. An unchanged profile or an unnamed task closes without this question. If work is running, Close first requests Stop and waits for completion; Cancel at the later profile question cannot resume already stopped work. Forced plugin unload bypasses interactive questions.

Use the **Profiles icon at the far right of the directory inputs**. Its menu lists saved profiles, marks the active one, and offers **Current panel directories** plus **Manage profiles…**. The panel entry restores the directories captured from the host panels when the window opened. Selecting an entry only loads settings; it never starts Compare or synchronization.

The active profile appears in the main window title and the icon's tooltip. An asterisk marks unsaved directory, mask, comparison-option or filter changes. In **Manage profiles…**, select a profile and use **Save current** to replace its settings with the current main-window values, **Save as…** to create a named variant, or Rename/Delete. The complete stored profile appears below the list: both paths, masks, five comparison choices and five result filters, each with an explicit On/Off state. Paths and masks are read-only and can be selected and copied. **OK** applies management changes and loads the selected settings when different; **Cancel** discards all changes made in that management session. Profile deletion never deletes files. Switching away from unsaved settings or existing results requires confirmation; a successful load clears the old comparison. Saving or renaming the current task keeps its comparison results.

The last selected saved profile opens next time. Only explicitly saved values are restored. **Keep originals, recovery directory, appearance, columns, sorting and relative display remain global**; the host's time tolerance is read for each comparison. Panel selection, highlighted rows, results and manual proposals are not saved. Use **Save profile as…** to keep a second variant. Profile management is disabled during an operation. Profiles have no scheduling or automatic execution in this version.

## Installation and launch

Use the compiled x64 ZIP with an x64 host. No compiler, SDK installation, or build step is needed. The plugin layout is:

```text
plugins/dirsync/dirsync.spl
plugins/dirsync/lang/english.slg
plugins/dirsync/lang/czech.slg
```

Close instances using an older plugin, copy the entire `dirsync` directory into `plugins` beside the program, and retain this structure. Open **Plugins → Plugins Manager → Add…**, choose `dirsync.spl`, and check the Directory Synchronization entry. Do not add it again if already registered by your distribution. Launch **Plugins → Directory Synchronization → Directory synchronization…**. Both roots must be physical Windows paths; archives and virtual plugin filesystems are not supported inputs.

**Updating from 0.2.1:** close every host instance using this plugin, back up the host configuration and optionally export profiles, then replace the contents of the existing `plugins/dirsync` directory with the complete new package. Keep the host configuration and recovery directories; do not remove and re-add the registered plugin. Settings, saved profiles and the last selected profile are kept. Both language modules must be updated together with `dirsync.spl`; the host selects its language when loading the plugin. After restarting, open the plugin once before checking its new version in Plugins Manager: an unloaded entry can still show cached metadata. [0.3.0 installation and upgrade verification](directory-sync-plugin-distribution-030.md).

Developers can build with `pwsh -File tools/build.ps1 -Configuration Release -Platform x64`; both language modules are dependencies of `build-support/dirsync.vcxproj`. Standalone build, test, and packaging instructions are in the [repository README](https://github.com/majklvi/salamander-directory-sync/blob/main/README.md). Historical distribution records remain dated evidence of earlier checks.

## Immediate removal of selected items

The row context menu has a separate **Remove selected… → Left… / Right… / Both sides…** section. It removes only highlighted visible items on the explicitly chosen side, regardless of their proposal, including Skip or Equal. This does not execute the visible synchronization plan. Normally it uses the **Windows Recycle Bin**. Holding **Shift while activating the specific side command**, for example Shift+Enter in the submenu, selects **permanent deletion without the Recycle Bin**. Pressing Shift at the later confirmation does not change that mode. The confirmation shows the mode, side, actual item count, and paths. OK performs that action; Cancel leaves it unchanged. Missing counterparts, blocked items, and read-only items are excluded.

**Keep originals does not apply to this direct command:** it creates neither synchronization recovery copies nor a synchronization journal. Restore recycled items through the Windows Recycle Bin. Permanent deletion has no plugin recovery. There is no fallback from recycling to permanent deletion: the Shell operation requires recycling, and its callback rejects non-recycling removal. An error stops the rest of the batch. Only empty directories are removed, after files and deepest directories first; selecting a parent does not include its contents. Unselected, mask-excluded, or filter-hidden files therefore protect their parents. A directory with its own ADS is rejected. The snapshot is revalidated before the operation, then each item's identity and metadata before acting on it. Stop beside Synchronize and Close request cancellation; an in-progress Shell operation may not stop within one item. Completed changes remain. A removal attempt invalidates the preview and requires Compare again. [Implementation and checks](directory-sync-plugin-immediate-delete.md).

## Appearance and help

While choosing an operation under **Synchronize…**, the left status pane explains the highlighted command, its scope and (for overwrite/delete) the current recovery choice. These commands use all visible eligible proposals, not just highlighted rows. The same help is available in the context menu's **Visible plan** submenu. Mouse and keyboard selection both update it; closing the menu restores the previous status. The other status panes retain their counts; if the window is too narrow, the complete text is available in the status pane's tooltip.

The main columns are symmetric: **Name | Size | Modified | Action | Modified | Size | Name**. The first three belong to the left root, the last three to the right. Optional State, Reason, and Error follow the right name. Headings omit the side by default; **Settings → Columns → Show side names in headers** restores explicit left/right labels. This remembered preference does not change ordering, results, or sorting. Visibility controls always name the side explicitly so the two size/date columns can be distinguished.

Since **0.1.3**, **Settings → Columns** offers independent **Show sizes relatively** and **Show times relatively** preferences. Both default to off and survive restarts. For paired files at the same relative path, differing sizes can become `1,024 B larger`, and differing times `2 d 3 h newer`; the other side shows `smaller` or `older`. Sizes use exact byte differences and the host's digit grouping. Time is elapsed UTC duration with 24-hour days and nonzero days, hours, minutes, and seconds. Fractional seconds are not displayed; a subsecond difference has a `less than 1 s` label. Equal values, unpaired entries, and directories keep the host's absolute format. This is presentation only: it does not change tolerance, state, proposals, or sorting by actual values. A relative time may therefore appear on a row considered Equal within tolerance. OK redraws existing results without rescanning; Cancel preserves the previous preferences. Columns expand as needed for typical labels and can be resized manually. [Relative display checks](directory-sync-plugin-relative.md).

Since **0.1.2**, clicking a column heading sorts files within each directory ascending, and another click reverses the order. Directory groups retain their order. Sizes, timestamps, and error codes sort by actual values; text sorts by displayed names without case sensitivity. Empty size/time values precede populated values ascending and follow them descending. Names break ties. The heading indicator identifies the active sort and direction.

Right-click a heading for the column menu, or use **Settings → Columns**. The file-row menu has no Columns entry. Both sizes, both timestamps, State, Reason, and Error can be hidden independently. **Both Name columns and Action are mandatory; the directory path remains visible in its group heading.** Hiding a column changes neither visible files nor operation scope. Hiding the active sort column restores ascending name sorting. Visibility and sorting are remembered across host restarts. Widths are restored within the current window when a column is shown again, but are not persisted across restarts. Sorting and columns cannot be changed while work runs. [Column checks](directory-sync-plugin-columns.md).

Since **0.1.1**, results are grouped by relative directory. `\` denotes the root and `\alpha\nested\` a subdirectory. Each name column shows the final item name only when the item exists on that side. Matched items show their names on both sides; single-sided items leave the opposite name empty. Headings are not action rows and clicking one does not select its contents. A directory proposed for deletion remains a separate row in its parent group. Filtering removes a group when it has no visible items. Copy paths still uses complete real paths. [Grouping record](directory-sync-plugin-grouping.md).

Size columns inherit **Configuration → Panels → Show sizes**: grouped bytes, whole KB, or mixed units. They use the core formatting routines, including rounding and regional separators. Summaries labeled as bytes and exported counters continue to show exact bytes; the progress window uses the host's compact transfer units. **Show names** in the same configuration controls letter case for every component of the relative display path, including separate file/directory styles. Display does not change real names, the plan, manifests, or clipboard paths. Preferences are read when opening the dialog and when the host notifies the plugin of a configuration change.

GUI checks compared all **three size modes and six name modes** available in the host with its main panels, including Unicode names. A seventh legacy name-format value in the SDK is not offered by the current panel configuration and is covered by a native test. Checks used en-US regional settings, with comma digit grouping and a decimal point; the system locale was not changed. [GUI display checks](directory-sync-plugin-ui.md#2026-10-16--gui-porovnání-show-sizes-a-show-names).

The package includes `lang/czech.slg`, named **Synchronizace adresářů**. The host's normal language mechanism selects Czech or English on plugin load. Restart the host to complete a language change; the plugin has no separate language switch. Keep both SLGs beside the plugin in `lang`. English controls below correspond to Czech **Porovnat**, **Synchronizovat…**, **Nastavení…**, and **Zavřít**. Translation does not change journal or manifest formats.

Compare and Synchronize are stacked on the right, with Settings and Close alongside in the same two rows. Each operation button has a narrow adjoining Stop section marked ×. Square icon filters have the same height as the other buttons. In narrow windows they occupy two rows, with categories above and directions below; when enough room is available before Compare, they form a single row. Reflow preserves filter state and results. A short Masks edit is at the left; six comparison options form two compact rows to its right. Long masks can still be entered and scrolled horizontally. Time tolerance follows the host setting in Options → Configuration → General. Recovery and command scope are explained in tooltips and F1 help; overwrite/delete confirmations always show scope and recovery mode. Highlighted rows do not limit plan operations.

Open **Preferences** through **Settings…** in the preview or **Plugins Manager → Configure…**; these open the same dialog. Settings is disabled during work. OK applies appearance immediately while preserving results, manual proposals, and filters; recovery preferences apply to the next separately confirmed operation. **Show action labels**, off by default, adds text and widens Action. **Appearance** shows all seven meanings in two columns: equal, different, right/left copy, Skip, delete, and decision/blocked. Each has a native Salamander color button and symbol sample. Light/dark mode follows the host; there is no plugin theme switch. **Restore default colors** restores the current mode's colors only. A horizontal rule separates **Other settings**, with **Keep originals** and **Recovery folder**. OK saves appearance and recovery preferences; Cancel/Escape discards pending edits. The other mode's palette is preserved. Preferences use the host's ordinary configuration storage. Symbols distinguish meaning independently of color; highlighted items use selection colors.

**Color row text**, off by default, also colors filenames, sizes, timestamps, reasons and errors with the configured action color. Copy directions, deletion and decision/blocked use their existing palette entries; Action and State keep their own semantic colors. Skipped rows remain gray (the configured Skip color), and selected rows retain native selection colors for readability. The setting is remembered and applies immediately after OK without repeating Compare. Cancel discards the change; Restore default colors changes only the palette, not this option.

Tab/Shift+Tab navigate Preferences. Alt+L toggles action labels; Alt+E/D/R/F/S/T/B opens the corresponding color control. Alt+U restores default colors, Alt+K toggles Keep originals, and Alt+O focuses the recovery path. Enter saves; Escape discards edits.

The six comparison checkboxes apply only to the **next Compare**. Toggling them does not remove results or manual proposals and opens no confirmation. The status bar warns that results use earlier options. Proposal and execution commands still use the last completed comparison's mode, including asymmetry: merely checking Asymmetric does not turn an old plan asymmetric. Compare rebuilds the plan and discards manual changes. Panel selection immediately locks/unlocks root edits, but panel roots are substituted only at Compare. Editing the mask or paths directly invalidates the plan.

## Typical workflow

1. Open the intended roots in the left/right host panels and launch the plugin. Check both paths side by side. Each **…** button opens the native directory picker, starting at the entered path; Recovery folder has the same button. **Make New Folder** creates a directory immediately: canceling the picker or Preferences does not remove it. Canceling or choosing the same directory preserves results. Choosing another root updates its edit and invalidates the comparison, like typing a different path. The recovery choice is saved only by OK in Preferences. Browse buttons are disabled whenever their edits are disabled by work, Panel selection, or Keep originals OFF. Tab and Space/Enter operate them. **Panel selection** uses the combined original selection from both host panels and locks roots; it applies on the next Compare and is distinct from preview highlighting.
2. Set Masks and scan options. `*.*` includes all names. Separate multiple masks with spaces or semicolons, quote names containing spaces, and place exclusions after `|`, for example `*.txt | *.tmp`. Subfolders includes descendants. **Compare** only reads and proposes actions. Timestamp tolerance is read from **Options → Configuration → General** at each Compare. When enabled, the configured seconds (normally 2) are inclusive and timestamps are compared at whole-second precision; when disabled, timestamps must match exactly. Existing results retain the settings used for their comparison. If the SDK cannot supply valid settings, the legacy inclusive 3-second tolerance is retained. The separate one-/two-hour DST setting is not currently exposed by the SDK. By content compares the main data stream, not ADS, and does not replace the newer-timestamp precedence rule. With Ignore date, or differing data of the same age, choose the direction manually.
3. Review Action, State, and Reason. Action defaults to centered symbols; Preferences can add labels. Accessible text, action tooltips, and the status bar on keyboard focus retain their meaning. State has a symbol and text. Default colors use green for right-copy arrows and Equal `=`, blue for left-copy arrows, ochre `≠` for differences/single-sided entries, gray pause for Skip, and red `×` or `!` for deletion or decision/blocked. Skip text uses the Skip color; State's semantic color remains but is faded toward the background. Highlighted rows use selection colors. Color alone does not define an operation.
4. To change proposals, highlight rows and right-click or press **Shift+F10**. The upper section offers default proposal (Ctrl+D), mark Skip (Ctrl+M), mark copy right (Ctrl+L), copy left (Ctrl+R), reverse direction (Ctrl+W), and, in asymmetry, mark right-only entries for synchronization deletion. A right-only directory can be skipped, reset, or marked for deletion without changing descendants. These commands **only change proposals for highlighted visible rows**; they do not copy or delete. A snapshot check precedes the change; unsupported items are omitted and counts appear in the status bar. Icon filters **= / ≠ / file outline / → / ←** control equal, different, single-sided, and copy-direction visibility. Pressed means enabled; tooltips explain each. Filters are independent and combinable. Enabled categories are combined; direction filters further restrict copy proposals. English shortcuts are Alt+Q/D/N/G/H; Czech shortcuts Alt+H/D/J/G/K. Hiding an item does not move its highlight to another file; previously hidden selection is not restored when shown again. Blocked/conflicting rows remain visible.
5. Open **Visible plan → Plan summary…**. This separate menu section uses the entire visible plan, even without highlighted rows. Its execution commands process **all visible eligible proposals**, not just highlights. Hidden and Skip rows are excluded. Plan copy counts include new and existing destinations; each confirmation shows only items eligible for its command, with separate file/directory deletion counts. Other visible proposals are listed as omitted.
6. Choose **Synchronize…** at the top right (Alt+Y; Czech Alt+S), choose an operation, and inspect its confirmation. The same commands appear under **Visible plan**, separate from selected-proposal changes. They are disabled without a valid comparison or eligible visible items. **Copy visible new items…** creates missing file and physically empty-directory destinations only; **Overwrite visible files…** replaces existing destination files only. **Delete visible items…** removes right-only files and included directories in Asymmetric mode. Directory proposals require Empty folders; nonempty subtrees require Subfolders. Files go first, then deepest directories, only when actually empty. Common empty directories and roots remain. Skipped, filter-hidden, or blocked children protect parents; selecting a parent alone never includes its contents. Synchronize opens a menu: **Execute visible plan…** runs a combined batch, while the individual commands remain available.
7. Read the result and run **Compare** before another operation. It rebuilds proposals, so reapply manual Skip as needed. The status bar shows progress/counts. **Compare's right-hand ×** (Alt+T) stops scanning, content comparison, or proposal/summary validation. **Synchronize's right-hand ×** (Alt+P; Czech Alt+Z) stops the selected file operation, including its initial validation. Only the relevant Stop is active during work; both are disabled while idle. **Close** waits for the worker. Completed operations remain. Tab moves through controls. In tabular summaries, Ctrl+C copies the selected value and Ctrl+Shift+C the entire summary; both are also in the context menu.

Asymmetric treats the left side as the source: it proposes eligible new/newer left files to the right, and right-only items for deletion. It does not automatically overwrite a newer right file. Without history, a missing file cannot be distinguished as intentionally deleted or newly created on the other side.

Hidden/System entries are included if they match mask/scope, independently of the main panels' visibility. Row tooltips show H/S for left/right separately; direction and Skip colors do not change. A leading dot alone does not mean Hidden. Directories with their own ADS are rejected before deletion, rather than silently discarding that data.

## Keeping originals and manual recovery

**Keep originals**, in Settings, defaults to ON. Before synchronization overwrites/deletions, all included originals are saved and verified first. Choose an existing **Recovery folder** outside both trees that is not an ancestor of either. Recovery requires space for original data including ADS, and staging needs additional space for the current transfer. If backup fails, the destructive phase does not start. OFF is remembered and shown in confirmation; it makes no new copy of originals/ADS and uses no Recycle Bin. Older backups are not automatically deleted. The preference and Unicode path are shared plugin settings, not per-directory-pair profiles; the host stores them.

**Visible plan → Save visible originals…** separately saves original destinations of visible overwrite proposals. It performs no overwrite/deletion and does not replace the fresh recovery required by a later execution with ON.

Manual recovery:

1. Find the appropriate `pair-…/run-{GUID}` in the recovery root, using its session time and paths in `manifest.jsonl` (UTF-8, one JSON record per line). The result summary names the journal path. Deletion/overwrite sessions also contain `delete.jsonl` or `overwrite.jsonl`.
2. Match `planned` and `result` records by `item`: `original` is the old path and `saved` the copy's path. Use a successful `saved` result; `published: true` alone is insufficient. A complete recovery session ends with an `end` record whose state is `complete`. A missing ending or incomplete line indicates an incomplete session: inspect individual copies. The execution journal clarifies what was actually overwritten/deleted after backup.
3. First copy saved data to a **new name or empty checking directory** through ordinary host copying. Inspect content and required ADS/metadata before deciding to restore the original path. Overwriting an existing file during manual recovery is a separate user decision.

In practice, take the directory containing the `saved` file, open it in a panel with **Shift+F7**, focus the file, press **F5**, and specify a new full destination path in a separate checking directory. Do not copy the whole session into the original tree: it contains journals and auxiliary structure. GUI checks covered overwrite and deleted-file originals, Unicode ADS, and modification time. [Workflow evidence](directory-sync-plugin-workflow.md#2026-10-16--aktuální-průchod-včetně-ruční-obnovy).

Deletion manifests include `kind` (`file` or `directory`). Directory records have a separate empty directory at `saved`, and record the original relative path, modification time, and attributes. For recovery, create the original structure from directory records, including empty directories, then restore files. Apply final directory times/attributes after adding descendants. Each item has its own auxiliary path, so do not restore the entire session tree at once. [ON/OFF GUI recovery checks](directory-sync-plugin-directories.md#2026-10-16--gui-mazání-a-ruční-obnova) verified structure, empty directories, file data, ADS, and file modification times. F7-created directories had new timestamps; exact manual recovery of directory metadata/permissions was not covered.

Recovery copies are independent data, not hardlinks. They inherit recovery-directory permissions; original DACL, owner, and SACL are not stored for automatic restoration. Synchronization overwrites retain the destination DACL; new copies inherit destination-directory permissions. Main data, the supported complete ADS set, mtime, and Read-only/Hidden/System are transferred and verified, not every NTFS property. Read-only overwrite/delete targets are rejected.

## Known limits and verification status

- Runtime verification covers local NTFS x64 with the current SDK. SMB is untested; network reliability is not claimed. Win32 and ARM64 compile in CI but are not runtime-tested.
- A larger NTFS pilot compared 5,849 file entries and verified 111 new copies and 51 overwrites with recovery. Exhaustive accessibility enumeration of thousands of rows caused substantial delays in that Windows/UI Automation session; hiding Equal entries made the complete data workflow usable. Independent ordinary manual use of the full list without that load remains unverified. [Pilot evidence and limits](directory-sync-plugin-pilot.md).
- No global empty-directory cleanup, history, unattended execution, automatic restore, or old-backup cleanup. Empty-directory copying and asymmetric deletion of included directories are supported.
- Reparse/junction/symlink, EFS, and unsupported cloud/offline entries are blocked. Roots may not overlap. The plugin supports Unicode/long paths; navigation through such paths in host panels is a separate capability.
- The first error or Stop halts the rest. Completed copies/overwrites/deletions are not rolled back. Owned incomplete staging is cleaned when possible; inspect any reported residue. Created empty parent directories and incomplete journals may remain.
- OFF has no persistent execution journal in this version. With ON, a journal-write error halts later work but does not undo a completed change. This is not transactional backup or protection against power failure or arbitrary concurrent changes.
- ZIP and clean-configuration checks cover x64, not a signed catalog distribution or complete Inno installer. A shorter registration description fixes earlier disappearing registration: the tested host accepts at most 259 bytes. If an old preview disappears from the menu, add it again through Plugins Manager after updating files; retain old recovery data. Filter reflow passed light/dark GUI checks and geometry tests at 96/120/144/192/240 DPI. Metrics tests do not replace live host tests at another system DPI or moving between monitors; those remain unverified. Detailed records distinguish live GUI tests from controlled fault injection.

## Results context menu

Proposal commands are enabled only if they can change at least one highlighted row. Restore default proposal is disabled when all eligible rows already have their default proposal; marking a copy direction is disabled when every eligible row already has that direction. Mixed selections keep the command available when another selected row can change. Unchanged or ineligible rows are left alone. This also applies to Skip and deletion proposals; keyboard shortcuts safely leave redundant proposals unchanged.

Right-clicking a highlighted row preserves selection; clicking another selects it. Clicking empty space uses the current selection; proposal changes are disabled without one. The separate **Visible plan** submenu uses all eligible visible proposals regardless of highlighting, with separators around summaries, execution commands, and original saving. Ctrl+A selects only visible rows. No menu implicitly selects all results. Filter-hidden, blocked, and conflicting rows are not changed by proposal commands. Right-only directories in asymmetry support Skip, default, or deletion; a valid Skip can be changed again explicitly. Left-copy and reverse commands are disabled in asymmetry.

**Copy paths** offers relative, full left, and full right paths. **Ctrl+C** with list focus copies relative paths, one Unicode path per line, omitting missing sides. These are paths from the last displayed result, not a fresh existence check. Path copying remains available for an invalidated result, but proposal changes require a new Compare. Text edits retain their ordinary Ctrl+C and other shortcuts.

Default proposals belong only to the current comparison; a new Compare discards manual changes. Actual operations are separate Synchronize/Visible plan commands on all eligible visible proposals, each with its own confirmation. Viewing, content comparison, editing, renaming, printing, property copying, and the Shell menu are not part of this menu. [Research and implementation record](directory-sync-plugin-context-menu.md) distinguishes reference behavior from implemented scope.

## Profile transfer and empty directories (0.2.1)

Manage profiles offers **Export…** for the entire list currently shown and **Import…** for a versioned `.dsprofiles` file. Export is independent of the manager's OK/Cancel: it writes the shown list immediately. Import only adds profiles to the manager draft; **OK** saves them, **Cancel** discards that import. Name collisions receive a numeric suffix; existing profiles and the active selection are preserved. Import alone does not load a profile, clear the current comparison or start any operation. Stored directory paths remain unchanged and may need adjustment on another computer. Recovery, appearance, results, manual proposals and active-selection state are not transferred. The format is a bounded binary collection using the profile storage version, not a text configuration or executable script.

Enable **Empty folders** before Compare to include physically empty directories. **Copy visible new items…** copies eligible visible directory proposals in either direction alongside new files. Skip and result filters apply. Files/directories inherit destination permissions; empty directories preserve modification time and supported attributes. Directory ADS are refused. Contents excluded by a mask do not make a directory physically empty. Existing targets are never replaced by this command. Stop stops remaining items and cleans unpublished owned staging where possible; completed targets and necessary created parents remain. Compare again after execution.

## Combined visible-plan synchronization (0.2.1)

Choose **Synchronize… → Execute visible plan…** to run all eligible visible proposals after one confirmation. Highlighting does not limit this command; Skip, hidden, blocked and unresolved rows are omitted. The confirmation shows new files/directories, overwrites, deleted files/directories, directions and main-data bytes, original-data bytes, omitted/hidden counts, and the frozen Keep originals preference/recovery path. With recovery OFF, overwritten/deleted originals have no plugin recovery copy; the Recycle Bin is not used.

Order: new targets first, existing-file overwrites second, right-only asymmetric deletions last (files before empty directories, deepest first). Each existing adapter keeps its verification and recovery rules. Before later phases the pending items must still match the confirmed identities and metadata; completed operations do not authorize changes to other pending items. The first error or Stop ends the remaining batch and all later phases. Completed changes stay, without automatic rollback. The final report lists completed/planned counts, errors, unstarted items and available recovery manifests/journals. Compare again before any retry. Close requests Stop and waits before the profile-save question. There is no scheduling or automatic start.

Live GUI verification on 19 October 2026 covered complete mixed batches with Keep originals ON/OFF, Stop during a large new-file copy with ON, and Close during a large new-file copy with OFF. Later overwrite/deletion phases remained unstarted after cancellation, completed copies remained, and no staging residue was found. See the [combined GUI report](directory-sync-plugin-combined-gui.md) for exact coverage and the separate large-list automation limitation. This does not claim every phase/cancellation point or SMB support.
