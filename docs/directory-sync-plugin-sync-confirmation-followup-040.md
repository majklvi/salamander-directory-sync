# Synchronization confirmation follow-up — 0.4.0 development

Verified 2026-10-21 on isolated local NTFS data. No SDK change, SMB test or release publication.

## Behavior

The main preview's Close previously set cancellation directly, bypassing the native Yes/No question already used by progress-window Cancel. Main Close during file operations now uses that same question, defaulting to No. While it is open, the worker pauses cooperatively. No restores the preceding paused/running state and keeps the preview open. Yes requests cancellation and closes only after worker termination; completed changes remain. The later modified-profile question is unchanged. Explicit Stop, scan/validation Close and forced plugin unload remain direct; forced unload never waits for a user response.

No separate command was removed by the preceding compact-confirmation change, but moving all of them exclusively into the results context menu made them harder to discover. The main Synchronize button now uses the host SDK's existing split-button control. Its main part opens combined confirmation; its arrow offers Execute visible plan, plan summary, new-item copying, overwrites, asymmetric deletion, original preservation and export. Existing eligibility rules and status-bar help apply. Original preservation is disabled with Keep originals OFF. The Visible plan context menu retains the same commands. When a report is available but synchronization is ineligible, the main part also opens the command menu, preserving access to export.

Add **Allow overwriting / Povolit přepisování** to compact confirmation. It is checked initially if eligible visible replacements exist, disabled/cleared otherwise. Clearing it excludes replacements in both directions and their dependent original saves, while retaining selected new-file/empty-directory copies and independently selected asymmetric deletion. It does not change arrows, filters, profiles, Keep originals or interactive error policy. Available direction counts still describe available proposals; Details describes the selected subset. Confirmations initialize afresh; this batch-only authorization is not a new remembered setting. Previously, selecting a direction included its planned replacements with no independent override in the compact dialog.

The same four-field internal selection reaches plan construction, executor, report and progress budget. Excluded replacements remain distinct from hidden rows, execution Skip and unstarted work. CSV/text adds `selected_overwrites` beside the three existing combined-command selection fields. SDK and recovery schema are unchanged.
